Request writers 0x142145DE0 and 0x142146E60 bind
ObjectsVectorizedResourceUsers / get_objects and put_objects. The environment
getter supplies objectstore.dev.demonware.net, objectstore.cert.demonware.net
and objectstore.prod.demonware.net. GET uses /v2/core/users/objects/ and the
DW-Objectstore-ObjectIDs header. PUT uses that path, or /v2/users/objects/ when
tags require it, with the client/context query and optional validationToken
expansion. Writer 0x142145630 emits owner/name and optional objectVersion and
checksum cache hints. Native response tables 0x14269F860 and 0x14269F8E8 select
the real GET and PUT success readers. The GET reader validates the object/error
count and original request indices. The native error reader recognizes the
exact Error:ClientError:NotModified string and retains cached content.

Implementation
REST and service 193 use one object store, owner/ACL rules, metadata, checksums,
expiry rules, tags and atomic upload journal. Both transports preflight complete
requests and response size before publishing an upload window. Downloads verify
stored content and checksum before returning content or a cache response.
Each requested object produces exactly one indexed object/error result.

The local cache policy returns NotModified when at least one nonempty cache
hint is supplied and every supplied hint matches current metadata. Stale or
inconsistent hints return current content. The target establishes the optional
hint format and NotModified consumer; it does not establish the retail server's
cache predicate. This implementation deliberately records that distinction.

REST output uses the existing 256 KiB REST response limit. The older structured
transport retains its existing 65535-byte window. Consumed header names are
ASCII case-folded; duplicate ObjectIDs, Authorization or Content-Type records
are rejected. Header values, authorization credentials and object bodies are
never added to diagnostic logs. Unknown header names remain compatible.
Duplicate JSON keys, excessive nesting, malformed cache hints, unknown query
fields and mismatched method/body/content-type contracts fail before writes.

Related research did not justify adding placeholder success replies:
