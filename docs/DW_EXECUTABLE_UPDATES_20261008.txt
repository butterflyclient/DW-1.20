Implemented update flow
-----------------------
The EXE contains a statically linked Windows updater helper. It is extracted
beside the game automatically; players do not install Python, a proxy DLL or a
separate updater package. The game folder must be writable by the player.

At startup a worker hashes the actual executable and asks the configured INI
DW host for an update. The main/render thread does not download or hash files.
The client checks the existing pinned platform RSA-PSS/SHA256 signature, a fresh
request nonce, time window, exact base/target hashes and bounded file sizes.

The patch is applied to a new staged file, not the running EXE. Its entire hash
must match the freshly compiled target. The native patch-status getter reports
COMPLETE_RESTART (2) only after staging succeeds and the native patch work has
completed. The original global PATCH dependency fence is left intact.

The shipped ui/utils/fencepatch.lua creates PopupPatchingRestart. Its OK action
sets lui_system_restart_required directly; the native platform restart entry
is therefore connected in addition to Fences.PatchRestart. The helper confirms
that it is waiting on this exact game process. Replay's native deferred quit
path saves settings and exits. The helper then verifies the files again, uses
ReplaceFileW with a recovery backup, verifies the installed image, and launches
it from the same game directory. INI files and local player identity/profile
files are not included in any patch.

If the EXE is unknown/modified, a signature fails, the download is incomplete,
or reconstruction fails, no unverified executable is installed. The installed
EXE remains usable. Details go to replay-dw-client.log and
game_dx12_ship_replay_dw.exe.update\result.log. The latter directory also holds
the staged image and the exact old EXE backup after a successful replacement.

Multiple releases behind
------------------------
There is no dependency on installing successive patches. Every publication
creates a direct old-hash -> latest-hash delta for EVERY retained release.
Each delta is applied locally and compared byte for byte with the fresh target
before publication. Release numbers increase; hashes identify the actual code.

Retain data/executable-releases, including releases.json, every archived EXE
and its compiler report. A missing/changed archived release stops publication.
The uploader refuses a catalog which removes a previously published base's
upgrade path. Blobs are immutable and uploaded first. Only after remote hash
checks does an atomic catalog rename advertise the new release. Interrupted
uploads leave the previous catalog usable. Future publication needs no backend
restart. Keep protocol v1 and its signing trust supported for older clients.

EXEs from before this feature do not contain an updater. Those players need
one manual copy of an updater-enabled EXE. Retained deltas cannot add an update
check to an executable which has not downloaded anything yet. Internal test
builds preceding job 942699db867140ef must not be handed to players.

Normal build and publication
----------------------------
1. Run build-game.ps1 using the private compiler workflow. The default snapshot
   now builds/embeds the helper automatically from frozen client crypto and ABI
   sources. Explicit reviewed integration snapshots can retain a verified
   helper header. Existing linker/relocation/provenance gates still apply.
2. Finish the deployment/client checks and an appropriate native game test.
3. Run:
   python -B tools/publish-executable-update.py --image <fresh-compiler-exe>
       --build-report <matching-build-report.json> --release <next-number>
   The report directory must contain matching verification-report.json and
   relocation-audit.json. The original compiled EXE is never edited in place.
4. Run python -B tools/upload-executable-updates.py when publication is allowed.
   Default output: data/executable-update-publication.
   Remote root: /var/lib/replay-dw/updates.

HTTP uses the existing DW port 8085:
POST /updates/v1/check       fixed version-1 request -> signed 448-byte reply
GET  /updates/v1/patch/<sha> immutable delta bytes, streamed in bounded chunks
