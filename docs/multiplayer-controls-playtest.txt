Use game_dx12_ship_replay_dw.exe from the compatible root game folder.
The universal client ZIP supplies this EXE, its INI, a launcher and instructions.

INI controls, read at full game startup:
  unlock_all=0  Normal native unlock controls.
  unlock_all=1  Enable native unlock overrides and project maximum player rank
                and all original weapon XP/levels in the rebuilt DW UI getters.
                Earned local/server progression is preserved underneath.
  rank=0        Use saved progression and allow earned XP to continue.
  rank=1..55    Select that career rank's native XP threshold once when changed.
                Keeping the same setting does not reset earned XP each launch.
  bypass_update_restart=0  Check and install verified DW executable updates (default).
  bypass_update_restart=1  Keep a custom executable and skip its update/restart
                           enforcement. Backend publisher/data patches and
                           ordinary native restart requests still run normally.

Keep the normal defaults unlock_all=0, rank=0 and bypass_update_restart=0 for the progression test.
Player XP saves to %LOCALAPPDATA%\ReplayDW\player-progression.bin on that PC.
Settings continue to use the player's native local Replay settings/profile.
Restart after changing the INI; changing it while the game runs is not a reload.

One gameplay run:
1. Add/accept a friend through Social if needed. Send a party invitation. Confirm
   the recipient sees it, accepts it, and both players appear in the party roster.
2. Leave the party through the menus, then search Quick Play independently with
   compatible filters. Both players should enter one shared lobby on opposing
   teams. The native minimum lobby wait is 60 seconds from the lobby's wait period;
   it is not an additional 60 seconds for each arriving player.
3. Load Shipment and select loadouts. Confirm movement, combat and both players
   in the scoreboard. Let both clients remain active during the test.
4. Send text in match/lobby chat. Confirm the remote client displays the sender
   and message. Also test a private whisper through Social.
5. Enable the game's desired microphone/push-to-talk settings, check that neither
   player is muted, and test speech in both directions. Confirm actual audibility.
6. Compare each player's scoreboard ping. Values should be sampled per client,
   rather than both being copied from the local player's connection.
7. Earn a kill/objective and finish the match. Record both players' XP totals.
   Confirm the totals increase. The local progression file should update after
   the native XP notification. No server-side player provisioning is needed.
8. Compare com_optimized 0, 1 and 2 in the console. Zero disables the experimental
   profiles. One preserves the 3D scene's appearance; two is the aggressive profile.
   Return to 1 after comparison. The fresh build registers 1 by default.

Automatic matchmaking bot fill (20261011):
1. Open Multiplayer or Warzone's Play screen. One checkbox above the playlist
   entries reads "Fill lobby with bots". The same setting appears above the
   full playlist list, and stays in sync across these screens. It starts off.
2. Enable it before matchmaking. The current lobby host arms the backend,
   waits 30 seconds, then adds bots gradually over the following 15 seconds.
   Existing minimum-player and lobby-wait rules still apply. The match cannot
   start until the backend acknowledges the target and the native roster is
   present; slow acknowledgements may extend the wait beyond 45 seconds.
3. Watch the pregame roster with another party member. Retained bots must keep
   their names, operators and customized weapons as more bots join. A joining
   human replaces eligible bot space without changing the playlist capacity.
4. In BR, turn Party Fill off. Bots must not occupy the vacant teammate places
   reserved for that party. Other eligible squads may still be filled with bots.
5. Disable the checkbox for ordinary matchmaking. The existing fill_lobby
   command and operator-panel bot controls remain available when auto-fill is
   off. Private, offline, System Link and co-op games keep their own bot setup.
6. Confirm the entry that previously displayed PLAYLIST/BRSOLOSTIM_NAME2 reads
   "BR Stimulus Solos". An available native translation takes precedence.

Client-local alternate killcam playtest (when present in the published EXE):
1. In your game console, use alt_killcam 1 to enable it, or alt_killcam 0 for
   the ordinary killcam. This archived integer defaults to 0. Each player's
   own game configuration saves their choice; host sv_cheats is not required.
2. Have one client enable it and the other leave it off. Die to a grenade or
   another object that normally has a following killcam. The enabled client
   should see the recorded killer in first person in the main view and the
   object's actual following camera in the upper-right inset, below the header
   and victim label. The inset occupies one quarter of the screen's width and
   height, clear of the lower perks, weapon and player-card overlays. The other
   client keeps its ordinary killcam. A normal firearm kill keeps the ordinary
   player view.
3. Toggle it off during that killcam, then skip the killcam, respawn and finish
   the match. Check that the inset disappears and the normal camera returns.
   If changing display size, check that the next inset has the correct image,
   placement and aspect ratio, without a stale image from the previous view.
4. Repeat several grenade killcams through the moment the grenade leaves the
   recorded player's hand. The extra object render must not register another
   streaming client. Check the transition, skip, respawn and return to the menu.
5. Watch the throw, explosion and remainder of the replay. The main camera must
   remain in first person without a blended grenade image. Once the grenade is
   destroyed, the inset retains its last valid image until the killcam ends.
   Native camera cuts isolate temporal reuse during the two-camera portion;
   normal camera history resumes when the game returns to a single view.
