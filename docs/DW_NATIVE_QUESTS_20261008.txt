IMPLEMENTATION
prepare-replay-quests.py validates stage chains, capacities, names, mode/type
and duplicate IDs against the read-only native table before generating
src/replay_quest_data.h. No per-player server provisioning is required.

Service 125/4 returns the real default mission definitions when no nonempty
custom definition publication exists. It retains native pagination/filtering
and does not save a generated default as a manual publication override.
Service 125/5 lazily creates a known mission state with kind 15, target from
the asset, zero progress and inactive status, then activates it. Selecting
another known stage deactivates the previous active stage in the same mode.
MP, BR and CP selections remain independent. Explicit custom initial-state
publications take precedence; a matching publication without initialState
continues to withhold activation rather than falling back to a default.
Service 125/6 deactivates without resetting progress. Terminal states survive
retries. Native structured parsing validates the whole request before saving.
Saved selection changes have one flushed atomic states.json replacement.
