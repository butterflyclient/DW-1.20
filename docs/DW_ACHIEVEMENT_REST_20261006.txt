FIX
After the entire batch passes ownership/schema checks and durable publication
succeeds, the backend returns HTTP 200 with {"allSucceeded":true}. Failed
ownership, malformed layouts or persistence never receive that success body.
Existing event journals, binary/REST retry identity normalization, cross-transport
deduplication and first-party attribution remain in the same domain implementation.
This acknowledgement does not fabricate achievement unlocks or reward grants.

The handler now binds the exact native path, POST method, JSON Accept/Content,
all three query fields and both query/body titles to the authenticated title.
It accepts the supported title/iw8 contexts and replaylocal/iw8 client labels.
Encoded values and reordered query fields work. Duplicate/unknown query keys,
foreign titles, prefix aliases, trailing separators, fragments and invalid
percent encoding fail before event publication.

Root, account/batch, event and value JSON objects reject duplicate keys.
Unknown root/batch/event layout fields and excessive nesting also fail before
publication. Complete single-user and first-party multi-user bodies retain their
original supported layouts. Persistence failures retain the existing error path.

INVENTORY IMPROVEMENT
The REST inventory now tracks the incoming RDX builder only through full
64-bit register copies. It follows shared service calls only when the same
builder reaches the helper and the helper's actual setter. This resolves both
event writers to ae.demonware.net without relying on their SQLite names.
Partial writes, volatile-call clobbers, indirect branches and ambiguous services
cannot inherit a proven pointer. Call sites and helper paths remain in the ledger.
The shared parameter helper is classified separately from independent requests.

Current direct-builder inventory: 29 containing functions, 28 independent

This does not prove all indirect/inlined REST paths or native callback completion.
