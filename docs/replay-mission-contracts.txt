REPLAY MISSION EVENT CONTRACTS

The backend uses Replay's own quest_challenges.csv IDs, targets, next-stage
names, XP and item rewards. All 232 supported MP/BR/co-op stage descriptions
were recovered independently from shipped eng_global_mp and eng_ui fastfiles.
Both copies agree, including prior-string references. Localize decoding rejects
ambiguous stream prefixes and validates the entire declared trailing asset set.

Original ProcessParams: 0x140F35980..0x140F385DC. These research addresses are
not game hooks or backend dispatch addresses. Unicorn executes original parser

The retained table hashes are recorded for each case. Parser tests prove the
packed data contract, not delivery of gameplay events or native callback use.

MP kill fields:
  Param0 low 16: first weapon/equipment ID, resolved through mp/statstable.csv
                and loot ID tables. Blueprint names are not producer names.
  Param5 high 16: weapon/equipment class mask.
  Param5 bits 16..31: target-type mask; bit 0 identifies a player. The shipped
                script also emits kill for destroyed vehicles/equipment/streaks.
  Param5 low byte: attachment count; 255 means no_attachments.
  Param6 bits 16..31: means-of-death ordinal (9 headshot, 21 execution).
  version: 1; gamemode: 2 for MP (original AddGamemode 0x140F33A00).

The engine shares class mask 65 between DMRs and sniper rifles. Backend sniper
criteria also require the shipped weapon_sniper base IDs 30, 31 or 32.
Equipment class mask 1024 is generic equipment; 3072 identifies lethal equipment.
Kill events have seven packed parameters and bypass the <=4-parameter aggregate
event caches. A kill event is one action, regardless of its packed numeric values.

The shipped ScriptFile producer and original parser agree on separate weapon,
cash and cache pickup counters. Native caches can aggregate these counts.
Timer producers report gettime() differences in milliseconds; fractional units
persist as timerRemainderMs and are never rounded up. Original ParseOperators
instructions are also executed in the 192-case parser proof. Recovered script
and original-bytecode-correlated disassembly hashes are retained separately;
this is producer contract evidence, not a native gameplay run.

Original cache-decision instructions identify only driving, alive_in_gas,
alive_not_downed and pickup as cached families. Revive and Gulag reports use the
individual-action branch. The shipped revive producer reports [1,1] for self,
[1,0] to the player being revived, and [0,1] to the player reviving a teammate.
The latter two must not receive each other's mission credit. Invalid non-boolean
actor flags receive no mission credit. The shipped Gulag winner path reports
result 1, while the loser path reports 2. Mission results and their retries share
the existing flushed event/stage/XP/inventory transaction.

Replay's UI StringTable mp/achievementenginerefs.csv identifies enemy=9,
danger=10 and object=13. A different-build dump uses object=11; Replay instead
uses 11 for map_enemy. These values are bound to the current UI FF/FP hashes,
complete original reader walk and typed table export. The original parser now
loads the missing table through a verified supplemental asset manifest.
Boot Camp's first five stages are covered as a native-wire activation followed
by event/reward/successor transactions, without seeding intermediate heads.

Verdansk's native MapEnts root and entity char-array span have been correlated
to original loader instructions. All 47,545 encoded entities parse, retaining
numeric canonical keys and explicit literal-key records; 12 authored locale
area triggers are present. The shipped setupchallengelocales initializer instead
reads location_volume entities; 46 are authored in this MapEnts payload. Its
33 locale assignments are verified against the unchanged original GetByte
operands. Unknown volume labels retain no locale ID. Brush-model indices are
never used as locale IDs. The semantic MapEnts exporter still reports a failure
separately from the complete native reader walk and entity-span extraction.

contract_start Param0 is the player's first touching mapped locale, Param1 the
contract card's first touching mapped locale, and Param2 the operator mask.
The backend uses the card's location for "Start a contract at" missions; this
criterion is reconstructed from the shipped descriptions and actor/card fields,
not a recovered retail cloud rule. The original atoi path uses the first locale
in a pipe-separated producer string, not a bitmask or every touching volume.
Internal layover/airfield/transit labels are associated with Airport/Military
Base/Train Station using authored origins and UI area labels; those geographic
aliases are inferences rather than explicit aliases in the initializer.

The native common_br_mp StringTables supply mp/brmissions.csv and
mp/brkioskpurchases.csv. Its achievementenginerefs.csv is byte-identical to the
UI copy. Contract categories occupy IDs 1..11. The original contract parser
emits category, outcome, alive flag, team role and operator mask. The shipped
releaseteamonquest producer reports success=1/failure=2 to owners with role=1;
hunted targets receive role=2 with an inverted result. Only a successful owner
report earns completion; dead owner-team members remain eligible. Unknown
categories, invalid flags, failures and hunted-target reports receive no credit.
These criteria follow the shipped descriptions and producer fields, not an
unavailable retail cloud rule.

Armor consumption reports use_item with reference 7; collect_item with the same
reference is a different action. Loadout reports follow successful crate class
selection and identify preset=0/custom=1; both count for generic collection.
The shipped game_type_col maps br=24 and dm=5. A parser fixture with placement
column 5 does not establish BR placement semantics. Placement earning still
requires the separate delayed-event allocation-lifetime contract.

Credit requires a native version-1 report, a selected
matching built-in stage, a timestamp at or after activation, and current live
public matchmaking membership. The host session must remain authoritative and
the host document must say in_game. Private/custom games, tournament lobbies,
expired/disbanded allocations and stale sessions do not satisfy this gate.
MP player kills require all seven parameters and the player target bit. BR
pickup reports require four parameters; timers require two. Reported mode 2
must match MP and modes 8/24 must match BR. The published game-type script
identifies the allocation family; playlist context such as "big" is a build
namespace. Mixed-family allocations receive no credit without a selected-mode
binding. MP and BR selected-stage guards are independent.

The stage, successor selection, XP, inventory and event receipt share the common
flushed/recoverable achievement transaction. A kill which finishes one stage
does not also credit its newly activated successor. Only actual successor
activation emits ACTIVATE_ACHIEVEMENT. Completed successors are preserved.
Receipt retries refresh current absolute state and owned rewards without adding
XP/progress again or replaying the completion/activation UI. Archived receipts
retain the same mission identities. Serialized delivery checks reject snapshots
superseded by progress or a different selected mission in the same category.

Battle Pass and mission updates merge the same staged states/inventory document.
They never publish duplicate destinations in one transaction. Existing local XP
confirmation, weapon progression, rank entitlements and Battle Pass behavior
retain their original paths.
