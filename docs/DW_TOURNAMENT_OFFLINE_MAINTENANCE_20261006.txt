ISSUE AND RESEARCH
Managed tournament withdrawal/expiry already had a complete recoverable terminal,
enrollment, search, lobby and account-index transaction. Its callers depended on
an authenticated tournament request or an enrolled client's idle publisher. The
lobby publisher starts after the first authenticated connection and iterates live
socket endpoints. It cannot guarantee retirement with all participants offline,
or on a server that has not authenticated any client since startup.

IMPLEMENTATION
The existing HTTP listener invokes maintenance once per second, before its select
wait. No new thread, game hook or engine recompile is involved. Maintenance owns
the same service-store mutex as request dispatch and idle delivery. It recovers
the existing title journal, validates persisted enrollments/catalogs and visits
each unique enrolled managed competition through the existing retirement planner.

Title directories must be canonical, nonzero uint32 names, real directories and
not symbolic links. The scan is bounded to 1024 directory entries. Per-realm and
per-competition failures are isolated and logged without profile/token contents.
A prepared shared transaction must recover before new writes can proceed. A
malformed store does not authorize a fabricated disband or cancellation.

Valid retirement atomically publishes the existing complete terminal layout,
retired owned searches/lobbies/indexes and cleared readiness. Live publications
and unrelated competition assignments remain intact. Actual results are retained.
The existing reconnect publisher supplies exact native event 2012 after durable
completion; it does not publish successful disband while a write is blocked.
