REPLAY DW MODE AND OBJECTIVE MISSION EARNING
2026-10-10

Issue
Nine shipped mission stages had no earning rule for their specific game mode
or objective action. Generic kill counts cannot satisfy those conditions.

Research
Retained native ScriptFile 2244 contains initchallengeandeventglobals and the
mode lookup used by event producers. Its 39 game-type entries agree with the
unique decoded GetByte operand sequence. The shipped game-type table and
localize assets distinguish Gunfight (arena) from Gun Game (gun). The weapon
table identifies M19 as weapon ID 2. No addresses or IDs from another build
are substituted. Four BR variant values are outside this initializer and are
not claimed by the generated 39-entry definition.

Original ProcessParams execution proves seven-UInt64 kill packets put the
game type in Param2's upper 32 bits, independently of operator IDs below it.
Capture, plant and defuse retain two scalar UInt64 fields; their game type is
Param0. This parser ignores later mask/operator arguments from those producers.
Shipped onplant reports the defuse event; the combined bomb-action criterion
accepts both native event names. One report represents one completed action.

Fix
Generate src/replay_challenge_game_type.h from the retained target-build proof.
Add the kill game-type accessor and the full two-field objective packet layout.
Keep unknown fields intact. Add these shipped earning rules:
  1570: Team Deathmatch headshot.
  1589: Team Deathmatch player kill.
  1592: Headquarters player kill.
  10004: SMG player kill in Gunfight.
  10047: M19 player kill in Domination.
  1512 and 1588: Domination objective capture.
  1517: Headquarters objective capture.
  1590: Plant or defuse in Search and Destroy or Cyber Attack.
Existing session, public allocation, version, mode-family, activation-time,
transaction, reward and successor checks remain part of the earning path.
