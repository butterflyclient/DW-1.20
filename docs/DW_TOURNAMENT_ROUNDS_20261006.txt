REPLAY DW TOURNAMENT ROUND LOBBIES - 2026-10-06

Issue
- Automatic formation produced a native bracket, but ready teams had no round
  lobby, native create/join delivery or later-round matchmaking assignment.

Target-build research
- Original Replay StartMatchmaking 0x14104A450 writes tournament.team_size.
- Decoder 0x14213F1C0 defines event 2005 create and event 2001 join envelopes.
  Both carry the actual party search ID, lobby ID and native document strings.
- Native backend parser 0x1410451D0 consumes tournament_id, round_id through a
  UInt16 getter and lobby_to_tournament_team_ids with keys 0 and 1. JoinLobby
  0x1410443C0 checks the tournament ID against the client's cached competition.
- Wire IDs and layouts come from the original Replay database. The IW8 source
  oracle was used only to clarify behavior, not to transfer RVAs or task IDs.

Implementation
- Capacity publications can pin three/eight-team or four/sixteen-team round
  rulesets. Real party searches provide users, tokens, sessions and host data.
- Both teams must be complete, have preceding winners when applicable, and
  have fresh round-scoped readiness/acceptance from still-live sessions.
- The common playlist selector honors available-map policy. Missing maps or
  valid native host data leave the round unallocated instead of inventing them.
- The common lobby builder produces actual host/backend documents, registered
  native address/DTLS data, exact team rosters and global-to-local team mapping.
  Closed tournament lobbies are excluded from public/presence matchmaking.
- Native create/join callbacks retain the real party search IDs. No simulated
  native flags, seed friendships, game changes or extra ports were introduced.
- Bracket, enrollment, new lobby, affected searches and account assignment
  index commit through one flushed recoverable transaction. Retry recovers the
  same allocation. Current assignments and leases revoke stale queued pushes.
- The existing idle publisher restores bracket and allocated join delivery on
  temporary same-session reconnect. A given lobby/search is delivered once per
  connection. Host document updates still use the existing update path.
- Authenticated owned result submissions advance winners; later rounds require
  fresh readiness and update the existing search identity to their new lobby.
- Complete persisted bracket validation rejects allocated one-team matches and
  allocations without pinned rules or a PLAYING formation record.
