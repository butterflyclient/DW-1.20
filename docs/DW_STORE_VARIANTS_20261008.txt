Issue and evidence
  Native sale selection adds 20000 to the base bundle ID. Smart selection adds
  60000 when the buyer owns the CSV smart qualifier. Sales take precedence.
  The original purchase callback cannot expand these variant IDs through the
  base bundle table. Server ownership persisted but the native cache stayed old.

  A triggers-only JSON message also fails Replay's achievement dispatcher.
  Original 140F33650 requires type/name/reason before dispatch; 140F34CA0's
  kind-18 completion reaches 141B3B6D0's absolute inventory reader without
  player XP or weapon progression handling.

  The SDK's reward version was a second blocker. Original 142125410 calls
  1420EFB80, which checks typed tag 3 and copies ONE byte. Its SQLite alias
  incorrectly says readUInt64. The old backend sent tag 10/eight bytes and the
  client rejected the message before the JSON callback. Both Store and existing
  player/weapon progression senders now send UByte8(1).

Implementation
  Catalog generation takes explicit sale base IDs, validates stock sale prices,
  preserves base bundle and visible/hidden child grants, and publishes both MP
  and Warzone sale variables. Smart offers require the stock smartID in durable
  buyer inventory before any debit or grant. No synthetic variant ownership is
  created. Missing sale prices and invalid smart qualifiers are rejected.

  Committed sale/smart self-purchases send the exact event-67 account/context/
  JSON envelope with kind-18 completion and absolute durable item quantities.
  Sorted refresh item IDs are protected by the existing receipt checksum.
  Retrying a saved transaction returns the saved completion and refreshes current
  quantities without another debit or grant, even after offer withdrawal.
  The existing atomic purchase/journal recovery paths remain authoritative.
