Replay DW Stim and Double Time earning, 2026-10-10

Implementation
Stage 1558 accumulates native integer Stim-health amounts toward 2500 health.
Stage 10006 counts player-target SMG kills with Double Time in any of the three
native perk slots. The perk ID is generated from the verified perktable row
specialty_hustle; it is not a guessed weapon/perk number.
The achievement transport previously maintained a separate earning-event list
which omitted stim. Admission now lives beside the mission rules and preserves
the existing match membership, category, version, activation-time and retry
checks. Unknown event families do not acquire an earning rule.

Target evidence
221 original Replay ProcessParams executions verify the packed fields and
scalar conversion. Stim input 17.500000 produces 17, sub-unit health produces 0,
and 2483.999 produces 2483. Double Time resolves to ID 7 in all three perk slots.
Primary quest definitions and localized descriptions supply targets and rewards.
This reconstructs shipped behavior; it does not recover retail cloud rules.

Fixture corrections
An accepted zero-credit event legitimately changes its receipt journal. Tests
assert unchanged mission state, inventory and player/weapon XP instead of
requiring every journal byte to remain unchanged.
The disposable successor stage is reset before testing fresh auto-activation;
an already completed successor should not be reactivated by production code.
An asynchronous absolute-XP snapshot can arrive on either side of a task result.
The receiver matches result kinds and current accepted XP, keeps every packet
in diagnostic history, and retains completions, rank-ups and product grants.
A new-rank snapshot cannot replace its completed notification. Explicit retries
and recovered commits expect inProgress refreshes rather than another rank-up.
No backend validation or transaction rule was weakened to pass these tests.
