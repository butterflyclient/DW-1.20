REPLAY DW ORIGINAL-INSTRUCTION TASK INVENTORY
2026-10-06

Issue
The exported assembly inventory uses continually changing SQLite aliases. Its
register tracker misses conditional moves and values saved in stack locals.
Those omissions hid the original mail sender's task 7/task 9 selection even
though both backend handlers were already registered.

Implementation
tools/inventory-native-task-bytes.py independently scans original executable
sections for direct calls/jumps to the three verified task constructors. It
decodes bounded control flow from function entries before accepting raw call
candidates. PE unwind bounds take priority; one function uses a SQLite start
and size hint. SQLite names are display labels, not call resolution inputs.

The tracker follows register widths, argument forwarding, nonvolatile registers,
conditional-move alternatives, saved stack locals, stack adjustment and frame
pointers. Volatile registers, overwritten/shadow stack slots and escaped locals
are invalidated conservatively. Unknown memory values remain unknown. Direct
forwarding wrappers are revisited for at most six passes. Each function is
limited to 10,000 states; no flag or branch-feasibility solver is claimed.

tools/test-native-task-bytes.py passes 24 independent x64 cases covering those
rules, including overlapping writes, unknown memory mutation and escaped
stack pointers. These cases exercise the analyzer; they are not backend task
fixtures or native game callback tests.

tools/inventory-backend-coverage.py now accepts the audit only when its target,
tool, test and raw-inventory hashes match. It independently rechecks all bounded
function byte hashes and every accepted direct call/jump target against the
untouched PE. Literal routes join the ledger's route set and retain separate
original_byte_callsite_proofs. A new backend binary cannot inherit completion
from this static evidence or from earlier native game tests.
