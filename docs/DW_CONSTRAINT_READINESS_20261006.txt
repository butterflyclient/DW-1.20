REPLAY DW PRIMARY-SLOT AND PLATFORM READINESS
2026-10-06

Issue
Lobby creation and joining counted primary account IDs only. Replay separately
requests a secondary split-screen slot for a primary sharing its token.
The backend also ignored acceptable_platforms when assigning a lobby.

Research
Original 1.20 StartMatchmaking 0x14104A450 emits primary IDs/tokens and a
0-or-1 additional reservation per primary. GetClientPlatform 0x1410AE340
returns 2, and 0x1410AE2F0 maps that value to bnet. Cross-play-disabled
searches explicitly request bnet. The current local realm authenticates
Replay PC; foreign-platform strings do not create foreign-platform identities.

Fix
Creation, public joins and presence joins count primary plus secondary slots.
Existing-primary presence reassignment replaces rather than doubles its count.
Backend documents publish the validated reservation map. Team occupancy and
fullest-lobby selection use the same counts. Departure removes reservations
through the existing atomic lobby/search/index transaction.
Malformed/nonmember reservation data and oversized parties fail unchanged.
Platform requests must be bounded unique arrays and must allow bnet. Equivalent
restricted/unrestricted PC settings can still match. Historical documents with
no reservation/constraint field remain compatible with zero secondary slots.
Persisted invalid reservation ownership/capacity fails rather than circulating
an inconsistent lobby. No engine patch, host endpoint invention or new port.
