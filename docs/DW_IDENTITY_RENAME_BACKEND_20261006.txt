2026-10-06

IMPLEMENTATION
The existing REST task 255/10 now handles uno / UserResource / renameUsername.
The original Replay writer at 0x142100230 uses PUT, JSON userName, the path
/v1.0/users/{auth-info.userID}/securedfields/?client=replaylocal and an
Authorization header with two spaces after Bearer. Both the native two-space
form and ordinary one-space form accept only the issued 64-byte access token.

The backend requires a live, unexpired lobby identity and a legacy access token
issued to that exact user/title/IV/session key. A different account path, token
from another session, stale token, malformed request, invalid name or name
collision cannot rename the player. Diagnostic operation labels include no
token, header/body contents, player name or identity key material.

The mutation selects the existing platform identity or named fixture profile or
machine-keyed player profile. It never provisions a new player. It validates
the complete persisted identity against the live canonical record before
changing it, flushes a temporary file and atomically replaces the same profile.
The in-memory canonical name changes only after publication succeeds. IDs,
platform account mapping and signed session payloads remain intact. Exact
same-name retries do not rewrite the file. Lookup/search use the canonical name.

Player INI names remain explicit login overrides. A nonempty player_name can
replace a backend-renamed display name on the player's next signed login.
The machine's private identity file is not edited or distributed by this route.

NATIVE CONTRACT
Original constructor 0x1421005E0 installs response vtable 0x14269E3D0.
Slot 1 is 0x142100900: JSON success field, error code at response +40.
Slot 2 is 0x142100670: numeric UNO error reader; 0x1421009B0 reads code/name/msg.
Successful committed changes return HTTP 200 and {success:true}. Ownership/token
failures return HTTP 403 with UNO 220000; invalid names return HTTP 400 with
214500; occupied names return HTTP 409 with 214500. Persistence faults remain
task failures. No failed write is reported as a successful rename.

This is the local account policy. It does not issue retail rename inventory or
claim to implement retail rename-token billing. The original engine owner at
0x140F2E750 checks rename inventory/currency and uses CrossplayAccessInfo's token.
The current legacy login does not establish that native crossplay rename flow.
The native rename menu callback remains unverified; protocol fixtures are not
a substitute for that callback.
