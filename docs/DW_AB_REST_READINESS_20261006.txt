REPLAY DW AB ENROLLMENT TRANSPORT AND MULTIPLAYER READINESS

Implementation
The explicit abtesting / abtesting / enroll REST domain shares the existing
task-194/1 account-owned enrollment implementation. It accepts the original
bodyless POST shape and relative abtesting/v2/users/<account>-<id>/enrollments/
URI, JSON Accept and no Content-Type. UNO and registered Battle.net aliases bind
the same signed account. Title/context, cohorts, revision protection, schedules,
token persistence and atomic-write failures have one implementation for both
transports. No profile, friendship or experiment is provisioned by default.

Native body boundary correction
The untouched Replay reader 0x1420FF640 uses an 8096-byte string buffer including
the terminator. The previous backend's 16000-byte upper limit could acknowledge
an enrollment that the native legacy client could not read. Both transports
now preflight a maximum of 8095 serialized JSON bytes before saving state. Eight
enrollments, one treatment each and 1023 modifier bytes per treatment remain the
independent native capacities; JSON overhead/escaping still counts toward the
shared body limit. Overflow preserves the last committed token and enrollment.

Exact target research
Original request writer 0x1420FFE50 sets POST, JSON Accept, resource abtesting,
operation enroll and the relative URI. It does not set serviceName. Builder
constructor 0x1420FC2C0 clears that field at offset 24416; original validator
0x142169540 rejects the empty field before sending. The research tool executes
the validator's original instructions in isolation, with external utility calls
explicitly stubbed. This confirms a client-side pre-transport blocker; adding
an explicit backend service does not correct that writer or prove a native REST
callback. The existing native engine enrollment path uses legacy task 194/1.

The REST response handler is 0x1420FF850 at slot one of vtable 0x1423F0028.
Constructor 0x140F28A60 installs that vtable at response offset 16. These bindings
are verified from original PE bytes rather than trusting database display names.
The game executable was not changed or recompiled for this backend integration.
