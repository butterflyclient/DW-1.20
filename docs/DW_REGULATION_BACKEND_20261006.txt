Implemented

Publication and ownership
data/regulations/<title>/publication.json is a bounded JSON object with schema=1,
the exact unsigned title, and a regulations array. Each array element has exactly
name and unsigned version. Names are unique, nonempty and fit the native buffer.
The whole document is validated; more than 15 entries, duplicate keys, trailing
JSON, noninteger versions and malformed names fail before data is returned.
An absent publication returns unavailable, rather than inventing an empty policy.

data/regulations/<title>/preferences/<signed-owner>.json contains schema, title,
owner and optouts. Each record contains regulation, clientMessageVersion, value,
updated and updatedTimestamp. Full ownership, uniqueness, capacities, types and
matching UTC/time layouts are revalidated on every read/write.
The local signed provider's uno/bnet representations select the same owner ID;
another owner's request is denied. URI values never become filesystem paths.
Only the existing authenticated owner can submit a real preference change.
The stock writer's regulation version zero selects the explicitly published
current version. A nonzero conflicting version or unpublished name is rejected.
Existing choices are retained if publication later changes or disappears.

Persistence
Reads use one bounded immutable Windows handle with delete sharing. Writes use
a flushed pending file followed by atomic replacement. A failed publication
cannot acknowledge success. An identical choice/version retry does not rewrite
the preference or its timestamp. Restart preserves the exact owned record.
The service-store lock serializes requests with the existing backend domains.
