Issue
The server's 23/2 fixtures passed, but the shipping game had never requested a
counter download. Its seven CSV-defined cached totals were still -1.

Target research
The untouched Replay getter at 0x1414F2320 returns the indexed cached total and
sets the native read-request byte. The original frame at 0x1414F26F0 dispatches
the SDK download, decodes the result and retires its native task. No existing
console command calls that getter. Indexes refer to CSV rows, not counter IDs.

Implementation
tools/prepare-native-counter-read-test.py freezes the verified shipping private
integration and adds an opt-in dw_localTestCounter command in private C++.
It requires the main thread, an initialized table and a bounded row index.
It calls the original getter; it never writes cache values, task state or fences.
The compiler resolves placement and all references. The current shared engine
profile compiled 81 C++ modules, so this private image is not represented as the
shipping image with only one byte or function changed.

The private filename must end in _dw.exe to activate the local DW provider.
The initial diagnostic filename did not; it was corrected without recompiling.
